# 実機検証チェックリスト — レストタイマー振動通知（指示書②）

TestFlight 配布後、実機（iOS）で手動確認する項目。ブラウザ・Playwrightでは検証できない
ネイティブ挙動（バックグラウンド通知・振動・許可フロー・フォアグラウンド抑制）を対象とする。

- 対象: ガイドモードでレストタイマーが自動起動する構成（設定でレストタイマー ON / 自動開始 ON）
- 通知ID: `1001`（レストタイマーは同時に1本のため固定）
- 前提プラグイン: `@capacitor/local-notifications` / `@capacitor/haptics`

## 1. 許可フロー（初回文脈での要求）

- [ ] インストール直後、**アプリ起動時には通知許可ダイアログが出ない**こと
- [ ] **初めてレストタイマーが起動した瞬間**（ガイドでセット保存→休憩開始）に通知許可ダイアログが出ること
- [ ] 「許可」を選ぶと以降ダイアログが再表示されないこと（2回目以降のタイマーで再要求しない）
- [ ] 「許可しない」を選んでも**アプリがクラッシュせず**、画面上のタイマー表示は正常に動くこと
- [ ] 設定アプリで通知を後から許可に変えた場合の挙動（次回タイマー起動時に予約されるか）を確認

## 2. バックグラウンド／画面ロック中の通知発火

- [ ] タイマー起動 → **アプリをバックグラウンドへ**（ホームに戻す）→ 終了時刻に通知が発火すること
- [ ] タイマー起動 → **画面をロック**（スリープ）→ ポケットに入れた状態でも終了時刻に通知が発火すること
- [ ] 通知の文言が「休憩終了 / 次のセットを始めましょう」で表示されること
- [ ] 終了までの残り時間が正しい（予約時刻＝タイマー終了時刻）こと
- [ ] 端末の通知設定（サウンド/バナー/触覚）に従って発火すること

## 3. フォアグラウンド時の振動と二重通知の回避

- [ ] タイマーを**画面表示したまま**終了させると、**Haptics 振動**（＋サウンド設定 ON なら音）で知らされること
- [ ] フォアグラウンドのままの終了で、**通知バナーが二重に出ない**こと（振動/音のみ、バナーは出ない想定）
- [ ] 「振動」設定 OFF（`restTimerVibration` OFF）では**振動しない**こと
- [ ] レストタイマー設定 OFF では通知も振動も一切出ないこと

## 4. 予約のキャンセル／再予約（背面化と組み合わせて確認）

- [ ] タイマー起動 → 背面化（予約される）→ 復帰して**「スキップ」/停止** → 再度背面化しても**通知が出ない**こと
- [ ] タイマー起動 → **一時停止** → 背面化しても**通知が出ない**こと（終了時刻が未確定のため）
- [ ] 一時停止 → **再開** → 背面化 → 新しい終了時刻で通知が発火すること
- [ ] タイマー中に **「+30秒」** → 背面化 → **延長後の時刻**で通知が発火すること（古い時刻では出ない）
- [ ] 次のセット開始などでタイマーが張り直された場合、**古い予約が残って二重発火しない**こと

## 5. ロック済み設計の維持（回帰）

- [ ] **通常フロー（非ガイド）でセットを保存してもレストタイマーが自動起動しない**こと
- [ ] セット後確認モーダル / 7ボタン重量調整 / 縦5択RIR の挙動が従来どおりであること
- [ ] ガイドモードでのタイマー自動起動タイミングが従来どおりであること

## 6. フォールバック・異常系

- [ ] 機内モード等でもタイマー表示・カウントは正常（通知は発火しないが**エラーは出ない**）こと
- [ ] 通知を拒否した状態で一連の操作をしてもエラーlog/クラッシュが無いこと

## 参考: 自動テストでカバー済み（Playwright / Capacitorモック）

以下は `tests/rest-timer-notify.spec.js` で自動検証済み。実機では上記の実挙動確認に集中する。

- タイマー開始 → 背面化で通知予約（id=1001）→ 停止でキャンセル
- 通知許可拒否でもタイマーは `running` で正常動作し、予約は張らずエラーも出さない
- 通常フロー（非ガイド）のセット保存でタイマーが自動起動しない（`idle` を維持）
- フォアグラウンドのままでは予約を張らない（二重通知回避の中核ロジック）
